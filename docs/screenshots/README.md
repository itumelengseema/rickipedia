## Reproducible widget captures

These captures use the app's production screens, navigation, and `AppTheme.lightTheme`, rendered by Flutter's widget test engine at 390 × 1000 logical pixels (PNG output at 2× resolution). Pagination uses a shorter 390 × 600 viewport to make the four saved records scrollable. They are reproducible UI captures rather than emulator screenshots or evidence of platform release validation. The capture harness turns off Flutter's debug banner and loads Roboto and Material icons from the installed Flutter SDK/assets instead of the test engine's placeholder font.

The capture theme explicitly resolves the snackbar body's unspecified font family to Roboto, matching Android rendering; the test engine would otherwise use Ahem for that style. No production theme behavior is changed.

`tool/fixtures/screenshot_characters.json` contains character records 1–4 downloaded from the Rick and Morty API on 2026-10-13. `portraits/1.jpeg` through `4.jpeg` are their corresponding API portraits. The harness seeds Flutter's image cache with those files, overrides the repository with deterministic responses, and intentionally fails requests to capture error states. Regeneration needs no network connection.

From the repository root:

```sh
flutter pub get
flutter test tool/capture_screenshots_test.dart
```

The harness writes `list.png`, `search.png`, `details.png`, `list-error.png`, `search-error.png`, and `pagination-error.png` into this directory. Browse → details and browse → search use the actual navigation entry points. The pagination screenshot uses a synthetic `next` page and an injected failure to expose the snackbar. These are documentation artifacts, not pixel-comparison tests, and are not regenerated by the default `flutter test` command.

Character data and artwork originate from the [Rick and Morty API](https://rickandmortyapi.com/); the characters and artwork belong to their respective rights holders. The saved records/portraits support documentation only and are not bundled as app assets.
